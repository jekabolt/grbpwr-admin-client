**Свежий ворктри бэкенда — две кодогенерации до сборки:**
`buf generate`, затем `make generate-resend-client`, затем `go build ./...`.
`proto/gen/**` и `openapi/gen/**` под `.gitignore`; без второй команды сборка падает на

**Запреты.**
- **`go test ./internal/store/...` — НИКОГДА.** Бьёт в прод и дропает таблицы. Единственный
  разрешённый пакет под `internal/store/` — `./internal/store/migrationlint/...`.
- Ни `git add -A`, ни `git stash`, ни `amend` при живых параллельных агентах.
- Гейт сборки — `go build ./...`, **не** `make build` (ломает моки на этом маке).
- Моки не генерировать: пиненная mockery v2, v3 даёт ложную красноту.

**Гейт — три правила, одинаковые везде.**
1. *Положительный контроль:* считать **число исполненных проверок**, а не код возврата.
   Пустой список `--- FAIL` бывает ровно потому, что пакет не собрался. Проверено на этой
   волне: `go test ./internal/apisrv/admin/...` в свежем ворктри не исполняется вовсе

2. *Отрицательный контроль:* сломать по одному и показать, что покраснела **именно та**
   проба. Не покрасневшая на своей поломке проба сторожит мёртвый код.
3. *Пробы парами: цитата + мутация.* Одна цитата зеленеет и на мёртвой разметке.

**Базлайн.** На самих `beta`/`master` уже красные `TestUpdateColorwayRecipeRoundTrip` и
пять тестов `apisrv/admin` — не приписывать их себе. Сравнивать **число исходов**, а не

**Три вещи, которые легко сделать неправильно:**
1. **Агрегаты считаются в той же читающей транзакции**, что и страница (`total_runs`,

3. **`picture.tech_card_id = slot.tech_card_id` проверяет Go** в той же Tx: схема этого

   исчезновение плиты). Отказ — `foreign_card_plate`.

Пишущие транзакции уже SERIALIZABLE (`db.go:63,165`), читающие — REPEATABLE READ read-only
(`:69`), ретрай транзиентных — `:107-141`. **Изоляция не заменяет логическую
идемпотентность** и не отличает устаревшее намерение от свежего — это работа
`client_request_id`, `slot_rev`, `expected_lock_version`.

## W1-C · B-5 · документный путь

**Читать:** `10` §4.1–§4.3 и §5.1–§5.2, `11` §2.2, `17` П-Д и Э15а.

- `mood_note` по verbatim-протоколу «absent = сохранить» (образец — `cutting_coefficient`,
  `techcard.proto:1112`);
- `client_ref` — хранимый и круглорейсовый ключ строки выноски;
- **минт номера выноски в ХЕНДЛЕРЕ** `internal/apisrv/admin/techcard.go`, **до**
  `carryOmitted*` (`:389`–`:410`) и **до** `restampFreshSignoffDigests` (`:423`);
- **dto-мапа enum'ов `kind`** (`internal/dto/techcard.go:89-97`) — без неё `SIDE_L` с
  провода падает в конверсии. В плане не названа, найдена гэп-анализом.

**Алгоритм минта — гейт по `client_ref`, и это принципиально:**
- `number == 0 && client_ref != ""` → `++seq`, номер присвоен, `client_ref` сохранён;
- `number == 0 && client_ref == ""` → **легаси-ноль, не трогать никогда**;
- `seq = GREATEST(stored.CalloutSeq, MAX(входящих), присвоенные)`, едет в тот же UPDATE
  `tech_card`, что бампает `lock_version`;
- **ремапа переиспользованных номеров нет.**

*Почему гейт именно такой.* В `tech_card_callout` лежит `callout_number INT NOT NULL
DEFAULT 0` без UNIQUE (`0067:113`), дублирующиеся нули там законны. Правило «`number<=0` =
минти» перенумеровало бы их первым же сейвом с любого клиента — то есть сдвинуло бы
DESIGN-дайджест **массово, на всём проде, в момент выката** (`c.Number` хешируется явно,
`techcard_section_digest.go:283`).

*Почему в хендлере, а не в сторе.* Минт в сторе означал бы: дайджест считается по payload с
нулём, а стор пишет семёрку — **свежая подпись рождается протухшей** и не лечится
переутверждением ([[digest-write-vs-read-asymmetry]]). И до `:410`: `CarryOmittedCalloutGeometry`
сопоставляет по номеру, и выноска с номером `0` подцепила бы геометрию легаси-нуля.

**Пробы:** «легаси-ноль без `client_ref` не тронут»; «`client_ref` присвоил номер до
дайджеста»; мутация каждой.

3. **Состав заморозки выносок определить** (`17` П-Е): морозятся выноски на медиа плит;

## W3-B · B-7 · репетиция удаления карточки — не отрезается

## W3-C · F-5 · ARTIFACTS, минт, журнал

Три состояния корня: чек-лист предусловий | живой верстак `draft — no version yet` | полоса
представлений + лист vN + журнал + плашка расхождения.

**Правило, без которого экран и бумага разойдутся под одной подписью:** ARTIFACTS показывает
**ДОКУМЕНТ**, а не последнюю версию, и несёт плашку `differs from v3`. **Печать vN печатает

вести не нужно: шаг один.
