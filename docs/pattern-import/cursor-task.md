## 1. Цель и порядок приоритетов

Цель: каждая деталь каждого размера замыкается своей линией и попадает в DXF.
1. **Неверное замыкание хуже дыры.** Ни одной клетки «закрыто → неверно».
2. Каждая открытая клетка, которую можно закрыть честно, должна закрыться.
3. Вопрос оператору — только когда файл действительно неоднозначен.

## 2. Почему этот путь

Замеры 16 ноября (журнал, «Failure map» и «wdall»): на set40 открыто 1068 клеток из 4752,
на holdout40 — 486 из 3052. Почти везде краска на бумаге есть (пустая бумага ~5 %). Мешают
четыре вещи:
- **C3 — линия не присвоена ни одному размеру** (`GRADE_P2_LOOSE`): своя + неприсвоенная
  краска покрывают ≥ 95 % предсказания у 244–330 клеток set40 и у 72–114 holdout.
- **G — семейство «inconsistent»** (`GFIT_LOCAL`): уже измерено, +11 set40 / +3 holdout,
  0 потерь, 0 неверных.
- **C2 — коридор по разбросу семейства** (`GFIT_LOCAL_CORRIDOR`, только поверх `GFIT_LOCAL`).
- **C1 — крайний размер на шаг за последним якорем** (`GFIT_EDGE_ACCEPT`): корзина «edge»
  375 / 167.

Код всех четырёх правил уже написан и стоит за флагами `=1`, которые выключены. В браузере
`process.env` нет, поэтому сейчас эти правила не работают для оператора вообще. Остаётся
одно: включать их по одному через проверку на корпусе.

### М1 – М4. Правила по одному
Порядок: **М1 `GFIT_LOCAL`**, **М2 `GRADE_P2_LOOSE`**, **М3 `GFIT_LOCAL_CORRIDOR`**,
**М4 `GFIT_EDGE_ACCEPT`**. Каждый шаг включается поверх уже принятых.

Для каждого шага:
1. **База.** Сначала один прогон set40 + holdout40 на текущем коде (после М0 — это новая база;
   дальше база = прогон принятого предыдущего шага, повторно не гнать).
2. **Включение.** Тот же прогон с флагом `=1`.
3. **Проверка приёмки** (все пункты, оба списка):
   - `dxf-check`: закрытых не меньше, ни одной клетки «закрыто в базе → открыто» без причины

   - **0 «закрыто → неверно»:** каждая новая закрытая клетка проходит `nest-check.mjs` (обычный и

   - **картинки** (`piece-pic.mjs`): все новые закрытия, если их ≤ 30; иначе 30 случайных

     картинку оценить «верно / неверно / не понять» в таблице журнала.
4. **Решение (сам):**
   - ни одного «неверно» на картинках и все автоматические проверки чисты → **принять**:
     включить по умолчанию, выключатель `<ФЛАГ>_OFF=1`, обновить список env в
     `src/lib/pattern-import/CLAUDE.md`, коммит;

     взяло). Допустима **одна** правка правила, измеренная на сохранённых шотах/пробах

     выключено), журнал, следующий шаг;

5. Готово для шага: запись в журнале с числами (закрыто set40/holdout до → после, новые,

## 5. Как решать развилки самому

1. Правило не закрыло ни одной клетки, но и не испортило — отложить, не «подкручивать».
2. Порог правила меняешь только по замеру на сохранённых данных, одинаковый для всех файлов.
   Подбор порога под конкретную клетку запрещён.
3. Не трогать: E1–E4, `drawMaxShare`, коридор 1–2 мм в базовом режиме, `GFIT_TOL_PDF` (его
   повышение — тупик), всё из «Dead ends» в `src/lib/pattern-import/CLAUDE.md`.
4. Таймаут прогона = машина спала → перезапустить тот же прогон.
5. Тесты падают после чужих изменений вне pattern-import — не чинить, записать и продолжать.
6. Зона правок: `src/lib/pattern-import/**`, `scripts/pattern-import/**`, `docs/pattern-import/**`.
7. **`yarn lint`, `yarn format`, `yarn fix` не запускать никогда** — они переписывают весь `src/`.
   Форматирование: `npx prettier --write <твои файлы>`.
